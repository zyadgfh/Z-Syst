# Notification delivery

Laravel email delivery and the application's SMS gateways are disabled in code, including password-reset and verification emails. Email-OTP registration and resend endpoints return 503 rather than claiming a code was sent. The old API email-reset endpoints return 503; administrators need another secure account recovery process. Restart queue workers after deployment so queued messages use the new code. The email block rejects delivery rather than silently claiming it succeeded; previously queued mail may fail and require queue cleanup.

External identity providers (including Supabase and Clerk), Firebase, or other independent applications can send messages outside Laravel. Their authentication, confirmation, recovery and messaging settings must be reviewed separately; this repository cannot guarantee those external services are disabled. The application Supabase signup endpoint is disabled; direct Supabase API access and other clients remain subject to Supabase project settings.

Doctor attention push uses existing active Firebase tokens scoped to the selected users and business. Configure `VITE_FIREBASE_PROJECT_ID`, the client-side Firebase settings and VAPID key, and `FIREBASE_SERVICE_ACCOUNT_PATH` pointing to a protected service-account JSON file on the server. Never commit the credentials. A push is recorded as sent only when FCM accepts at least one token; FCM acceptance does not guarantee device display. Alerts remain available in the application if delivery fails, and recent alerts are deduplicated even if push is unavailable.
