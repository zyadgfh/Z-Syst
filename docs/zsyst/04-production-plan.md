- [ ] **الهوية**: إزالة أصول/شعارات القالب، اسم منتجك، شاشة دخول خاصة. — *الإنجاز: صفر إشارة للقالب في الواجهة الظاهرة.*
- [ ] **إزالة مخلفات الوكلاء**: `.agent`, `.agents`, `.blackbox`, `.bug-hunter`, `.claude`, `.cline`, `.windsurf`, و`inspect_options.php`, `refactor_acnoo.php/.py`, `temp_plans.html`, الملف `d`.
- [ ] **`LICENSE` + `NOTICE`**: ذكر صريح لأصل القالب وحدود الرخصة وما أُعيد بناؤه. — *الإنجاز: ملف موجود وواضح قبل أي عميل.*

> **لماذا الآن:** كل ما بعده يعتمد على بيئة قابلة للتكرار. بدونها كل إصلاح لاحق غير مُثبت.

## 4. المرحلة ١ — الإطلاق (١٤ يومًا)

### الأسبوع الأول

**أيام ١–٣ · العزل والصلاحيات** (أعلى مخاطرة في SaaS)
- [ ] مصفوفة عزل لكل جدول يحمل `business_id`: اختبار يثبت أن مستأجر A لا يقرأ صفوف B في **كل** مورد، لا في نموذج واحد.
- [ ] حسم `TenantResolver` كمصدر وحيد للحقيقة، ومنع أي استعلام بلا `business_id`.
- [ ] إغلاق التسجيل العام → **دعوة فقط** (كود دعوة/تفعيل يدوي).
- [ ] فحص كل `permission:` string مقابل البذور (كان 63 من 73 غائبًا) — اختبار يمنع التكرار.
- [ ] *الإنجاز: صفر جدول بلا اختبار عزل، وصفر صلاحية مُستخدمة غير مزروعة.*

**أيام ٤–٦ · تقليص النطاق إلى النواة**
- [ ] إخفاء الوحدات خارج النواة: تأمين، ولاء، GRN، تحويلات مخازن، وصفات، traceability، عملات، بانرات، خطط.
- [ ] **حذف/تعطيل وحدة الوصفات وربط المريض** نهائيًا في هذه النسخة (قرار رقم ٧).
- [ ] `feature flag` واحد يتحكم بالإظهار، لا تعليقات مبعثرة. — *الإنجاز: المسارات المُخفاة تُرجع 404/403 باختبار، لا تنكسر الواجهة.*

**أيام ٧–٨ · النواة تُثبت نفسها**
- [ ] تغطية اختبارات لمسارات النواة الإدارية: بيع، شراء، مخزون، تقارير (الفجوة الحالية: 6 من 17).
- [ ] بيانات صيدلية تجريبية (seeder واقعي: ٥٠ صنفًا، ٣٠ عميلًا، أرصدة).
- [ ] فحص أداء ابتدائي: فاتورة بيع بـ٢٠ صنفًا، صفحة أصناف ٥٠٠٠ صنف.

### الأسبوع الثاني

**أيام ٩–١١ · الاشتراكات والتحصيل**
- [ ] جداول `plans` / `subscriptions` / `payments` بحالة واضحة: `trialing → active → past_due → suspended → cancelled`.
- [ ] تكامل Paymob: `initiate` + **webhook موقّع** + idempotency + اختبار webhook مزيّف. — *الإنجاز: اختبار يفعّل اشتراكًا تلقائيًا دون لمس يدوي.*
- [ ] **تفعيل يدوي احتياطي** جاهز من اليوم الأول (لأن حساب Paymob لفرد قد يتأخر). — *الإنجاز: زر تفعيل + سجل تدقيق.*
- [ ] فاتورة/إيصال اشتراك عربي، وسجل مدفوعات.
- [ ] حجب ميزات بعد انتهاء الاشتراك + مدة سماح.

**أيام ١٢–١٣ · الاعتمادية**
- [ ] نسخ MySQL كل ساعة → تخزين خارجي مشفّر + احتفاظ + **تمرين استعادة فعلي** موثّق. — *الإنجاز: استعادة على قاعدة نظيفة في < ١٥ دقيقة.*
- [ ] `/health` (DB + queue + storage) + UptimeRobot + Sentry + تنبيه Telegram.
- [ ] `logrotate`، حدود موارد الحاوية، سياسة إعادة تشغيل.
- [ ] تشديد أمني: HSTS، صلاحيات MySQL بأقل امتياز، أسرار خارج الصور، `APP_DEBUG=false` مُختبَر.
- [ ] تنفيذ المراجعة الأمنية لكل ما سبق توثيقه (CSRF، XSS، rate limit، audit trail).

**يوم ١٤ · قرار الإطلاق**
- [ ] بروفة على staging بنسخة إنتاج + مستخدم حقيقي يجرب سيناريو يوم كامل.
- [ ] قائمة go/no-go: كل بند في هذه الخطة منجز أو موثّق كـ«مؤجّل بوعي».
- [ ] وسم إصدار + خطة تراجع (rollback) مكتوبة.

## 5. البنية التقنية المستهدفة

```
Internet → Cloudflare (اختياري) → nginx (TLS, HSTS)
                                   ├── php-fpm (Laravel)
                                   ├── worker (queue: database)   ← لا Supervisor
                                   └── scheduler (cron كل دقيقة)
                     mysql:8 (volume) + نسخ كل ساعة → S3-compatible
```

- **Queue على `database`** لا Redis: أقل مكوّنات، يعمل على أي استضافة.
- **`cron` بديل لـSupervisor** ليبقى النظام صالحًا للاستضافة المشتركة إن اضطررت.
- **الأسرار** في `.env` غير المرفوع + نسخة احتياطية مشفّرة، لا في الصور.

**تكلفة تقديرية شهرية:** VPS ٤GB ≈ ١٢–٢٤$، تخزين نسخ ≈ ١–٣$، دومين ≈ ١٠$/سنة، الباقي (Sentry/UptimeRobot/Telegram) صفر. عمولة Paymob تقديرية ~٢.٧٥٪ + مبلغ ثابت لكل عملية.

## 6. المرحلة ٢ — بعد أول عميل يدفع

1. **طابور البيع المحلي** (قرار ٩) — يُنفَّذ حين يوجد عميل يعاني انقطاعًا فعليًا، لا قبل.
2. **استيراد البيانات** — ابدأ بـCSV/Excel مع شاشة ربط أعمدة، ثم محوّل مخصّص لكل نظام يُطلب.
3. **إغلاق مسألة الرخصة** — إما Extended License أو استكمال إعادة البناء.
4. **تشغيل الشريك** لالتزام ٢٤/٧ فعليًا (تدريب + مناوبات + عقد).
5. **توسيع النطاق**: التأمين والولاء بعد اختبار حقيقي على عميل.
6. **الوصفات وبيانات المرضى** — فقط بعد سياسة خصوصية وأساس قانوني.

## 7. مخاطر مفتوحة لا أحاول تجميلها

| المخاطرة | الأثر | التخفيف في هذه الخطة |
|---|---|---|
| **رخصة Regular + SaaS متعدد** | إذا كان كل مستأجر «end product» فهذا خارج الرخصة؛ إعادة الهوية لا تمحو ذلك | مكتوبة في `NOTICE`؛ القرار الحقيقي (Extended أو استكمال البناء) قبل التوسّع |
| **«استيراد كل الصيغ»** | التزام غير محدود، لا يمكن تسعيره أو اختباره | خارج الأسبوعين بلا تاريخ؛ يبدأ بـCSV |
| **Paymob لكيان فردي** | قد يتأخر القبول أو يُرفض | تفعيل يدوي احتياطي من اليوم الأول |
| **٢٤/٧ بلا شريك بعد** | وعد لا يُنفَّذ | لا يُعلَن قبل توقيع الشريك |
| **لا عميل أول** | «جاهز للإطلاق» بلا مستخدم لا يُثبت شيئًا | بند تجاري في الأسبوع الثاني: ٣ صيدليات مستهدفة + بروفة على صيدلية حقيقية |
| **أسبوعان + نطاق كامل** | استحالة حسابية | النطاق قُصَّ فعليًا: نواة + اشتراك مبسّط فقط، والباقي مرحلة ٢ |

## 8. ما أحتاجه منك لبدء التنفيذ

1. **دومين** (أو موافقة على استخدام مؤقت).
2. **VPS** بمواصفات ٤GB / ٢vCPU (أو أجهّز Docker على جهازك أولًا).
3. **حساب Paymob** — بدء التسجيل اليوم لأن الموافقة قد تستغرق أيامًا؛ التفعيل اليدوي يسدّ الفجوة.
4. **اسم الشريك** للدعم (أو قرار تأجيل إعلان ٢٤/٧).
5. **قرار الرخصة**: أستمر على «إعادة الهوية فقط» أم أعيد النظر في Extended؟ — هذا يحدّد ما إذا كان `LICENSE` يقول «مبني على قالب» أم «مبني على كودي».
6. **قائمة ٣ صيدليات** نستهدفها في الأسبوع الثاني.

## 9. تعريف «جاهز للإنتاج» (بوابة الإطلاق)

لا نطلق حتى تتحقق كلها في وقت واحد:

- [ ] `docker compose up` يُقلع النظام من الصفر على جهاز نظيف.
- [ ] 365+ اختبارًا خضراء على CI **واحد**، مع اختبارات عزل لكل جدول وwebhook للدفع.
- [ ] فاتورة بيع كاملة من الواجهة: صنف → مخزون → تقرير → إيصال.
- [ ] اشتراك يُفعّل تلقائيًا من webhook مزيّف، ويُعلَّق عند الانتهاء.
- [ ] استعادة من نسخة احتياطية مُنفّذة فعليًا وموثّقة بالوقت.
- [ ] تنبيه يصل عند إيقاف الحاوية يدويًا (إثبات أن المراقبة تعمل).
- [ ] `LICENSE` و`NOTICE` موجودان، وصفر أثر لمثبّت Envato.
