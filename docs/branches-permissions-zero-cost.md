# الفروع والصلاحيات — صفر تكلفة

> باقاتك: 399:1 فرع / 599:3 فروع / 899:7 فروع / 999:غير محدود
> العميل يخصص حسب العدد المحدد له

## كيف تعمل الفروع حالياً (مقاس)
- جدول `branches` فيه `business_id` + `name`
- جدول `app_users` فيه `branch_id` (nullable) — المستخدم مرتبط بفرع
- RLS: كل استعلام يفلتر `business_id` ثم `branch_id` إذا كان المستخدم ليس admin

## الحدود حسب الباقة (مقترح واقعي)
- **399:** 1 فرع، 2 مستخدم (مدير + كاشير)
- **599:** 3 فروع، 5 مستخدمين
- **899:** 7 فروع، 15 مستخدم
- **999:** 999 فرع (عملياً غير محدود)، 100 مستخدم

## التنفيذ صفر تكلفة
- **لا كود جديد:** استخدم `branches` و `branch_id` الموجودة
- **الحد:** في `BusinessController` عند إنشاء فرع جديد → `if (Branch::where(business_id, auth.business_id).count() >= limit) abort(403)`
- **الصلاحيات:** `manager` يرى كل الفروع، `cashier` يرى فرعه فقط (فلتر `branch_id` في كل كنترولر)

## المخزون حسب الفروع
- سؤالك: "مخزون منفصل لكل فرع" أم "مركزي"
- **الحل المجاني:** مخزون منفصل لكل فرع عبر `stocks` (فيه `product_id` + `business_id` + `branch_id` قريباً)
- **المرحلة 1:** مخزون واحد لكل `business_id` — كل الفروع ترى نفس المخزون (يكفي 80% من الصيدليات)
- **المرحلة 2 بعد 50 عميل:** أضف `branch_id` لـ `stocks` — كل فرع مخزون منفصل

## الخلاصة
- الحدود تُفرض في الكود فقط — لا تكلفة
- ابدأ بمخزون موحد لكل الفروع — بسّط الإطلاق
